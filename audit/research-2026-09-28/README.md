## Proposals in Draft or Review (not shipped, not built on)

| SIMD | Status | What it would change | Hopper position |
|---|---|---|---|
| 0670 ABIv1 `invoke_signed_v2` | Review | one account slice indexed by instruction position instead of `AccountMeta` plus `AccountInfo`; the proposal's own benchmark shows CPI setup shrinking | Hopper's checked CPI already builds metas from views without an `AccountInfo` copy; when the syscall lands, `cpi::invoke_signed_with_bounds` is the one place to switch |
| 0568 deprecate precompiles | Review | secp256k1, secp256r1, ed25519 precompiles removed in favor of syscalls | `hopper_native` introspection of precompile instructions stays for existing transactions; the crypto helpers already call syscalls where they exist |
| 0646 disable legacy and v0 transactions | Draft | only v1 transactions after activation | `hopper tx send --v1` builds the surviving format; clients generated by `hopper compile` are unaffected on the program side |
| 0596 96-account lock limit for v1 | Draft | more accounts per transaction | entrypoint ceilings and `MAX_STATIC_CPI_ACCOUNTS` (64) are per instruction, not per transaction; no change |
| 0582 early instruction-trace overflow | Draft | counts top-level instructions plus executed CPIs against the 64 limit when a frame is pushed | a deep CPI fan-out fails earlier; Hopper's CPI depth is bounded by the caller, nothing to change |
| 0648 unbounded loader-v3 instruction data | Review | larger buffer writes with v1 transactions | deploy tooling only |
| 0645 SVM JIT intrinsics (`sol_multi3`) | Draft | 128-bit multiply lowered by the VM | `hopper_native::arith` already avoids `__multi3` for 64-bit checked products; if the intrinsic ships, wide multiplies get cheaper without a source change |
| 0376 relaxed signature verification | Review | cofactored ed25519 verification | none for a program |
| 0558 leader-info syscall | Draft | `sol_get_leader` | not a shipped capability; not wrapped |

## Peer frameworks

**pinocchio.** The `sdk` crate's entrypoint is the unrolled 255-account
walk; Pina's ADR 0010 measures it at 7,736 bytes on its counter. Hopper's
count-exact entrypoint parses exactly the bound and refuses surplus
accounts (`ERR_TOO_MANY_ACCOUNTS`). pinocchio has no alias check for one
account in two mutable roles; Hopper refuses it at bind
(`ERR_ALIASED_MUTABLE_ACCOUNTS`). The token crates were reviewed builder by
builder: pinocchio-token 0.7 ships 29 SPL Token builders generic over a
`TokenInterface` program plus `Batch`; pinocchio-token-2022 adds the
extension instruction families. Hopper had 19 of the shared builders and
none of the extension instructions; the 2026-09-28 tree closes that
(every shared builder, `invoke_on` / `invoke_for_owner` for the program,
`TokenBatch`, thirty-five Token-2022-only builders, `MintPlan` with thirteen
extensions), checked byte for byte and meta for meta against
`spl-token-2022-interface` 3.1.1 rather than against pinocchio.

**Pina.** The line-by-line report (scratch, sections 0 to 12) found: the
published benchmark table unchanged since `aa81c8d1` with PR #544 pending
(Pina counter 12,720 B / 3,295 / 1,753; lean fixtures 2,736 B hello); the
silent stack-frame overflow of `cargo-build-sbf` (Hopper's `hopper build`
and the bench now fail on it); trailing optional accounts accepted when
missing (Hopper now does the same); a CU ratchet in CI (Hopper's bench now
compares with the results committed at HEAD); sbpf-linker at -38% size on
Pina's counter (not yet evaluated on Hopper's fixtures); the `init` helper
writing the bump byte and per-field value validation (open).

**Quasar.** Reviewed at `b0de7db4` for the comparison rows only; its
account model (no borrow tracking, unchecked CPI by default) is the design
Hopper's checked tiers exist to avoid. No API in Quasar changed the
conclusions of the 2026-09-19 comparison.

**Anchor v2.** Reviewed at `e4878b6d`: the mutable-alias mask and the
program-id filler for optional accounts are the two behaviours Hopper now
matches or exceeds (alias refusal by record pointer; trailing optionals may
also be omitted, which Anchor does not allow).
