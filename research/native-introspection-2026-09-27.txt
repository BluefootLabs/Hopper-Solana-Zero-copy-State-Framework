Reviewed boundaries and consequences:

1. Agave syscalls/src/lib.rs:2015-2135 and the SDK's instruction/src/syscalls.rs
   sibling helper. The syscall returns one for found, zero for absent. It copies
   only when both requested counts equal the actual data and account counts;
   otherwise it returns the sizes. The SDK uses a probe followed by exact-size
   allocation. Hopper's wrappers instead treated zero as success and supplied
   capacities, so found siblings were rejected and missing ones could fabricate
   a zero-filled result. Published native 0.4.2/runtime 0.4.3 reproduce all four
   fixture regressions in compiled SBF. Fixed helpers query then copy into caller
   buffers. A data-only helper must still supply account scratch.

2. SDK instruction/src/account_meta.rs layout and both Agave SBF sibling fixtures
   were read. Returned account metadata owns its address, then signer/writable
   booleans (34-byte records), unlike CPI pointer descriptors. Compile-time ABI
   assertions and actual SBF tests cover this distinction. Agave scopes siblings
   by depth and caller. Pinned invoke_context.rs precompile processing uses push,
   process_precompile, pop; this source observation is not a new claim that the
   whole precompile authorization flow was devnet-tested in this release.

3. Pinocchio sdk/src/sysvars/instructions.rs: constructor, relative/absolute
   indexing, account records, program/data access. Its Instructions sysvar view
   is a separate transaction-level API, not a processed-sibling syscall wrapper.
   The validated account constructor binds the sysvar identity; unsafe byte
   constructors depend on caller validity. Pina crates/pina/src/introspection.rs
   distinguishes transaction-level instruction scans from stack-height guards;
   a current top-level program-ID comparison cannot detect self-CPI. Hopper's
   guide explicitly distinguishes these scopes and payload authorization.

4. Quasar lang/src/cpi/dyn_cpi.rs:1-316, initialization capacities and invoke/
   return-data boundary. It uses initialized-prefix tracking and a stack-budget
   check with an escape hatch. Its return path binds the return producer. These
   are useful baseline expectations, not unique Hopper ideas. Hopper already has
   checked caller-slice CPI and producer-bound typed return data; this patch adds
   caller-selected scratch sizes for instruction inspection. It does not claim
   a speed win over Quasar's CPI builder. Head unchanged from previous capture.

5. Pina's new validation.rs parsing boundary: comma/&& groups, named-parameter
   disambiguation, chained comparison parsing, exactly one receiver and equality
   restrictions; generate_comparison emits pairwise && checks. Reviewed the
   complete 52-line comparison compile fixture. This offers concise field rules;
   Hopper's ordinary Rust checks are not the same declarative API. No claim that
   a field rule proves transfer outcomes. Kit-8 scaffold and IDL-doc changes were
   inventoried from the compare response/changesets, not exhaustively reviewed.
   The large GitHub compare file list is truncated; fetched != audited.

6. Anchor v2 event.ts/index.ts migration patch: abort-scoped Kit subscriptions,
   per-notification errors versus fatal subscription failure, and provider API
   changes. This is client DX work, not a new native execution requirement or an
   on-chain performance result. Provider/test deltas were inspected selectively;
   no blanket SDK parity claim follows.

7. Sister scopes: abiv2 README deployment limitations and sdk/src/cpi.rs:1-210
   scratchpad/borrow contracts; Pinapod traits.rs:1-150 representation validation
   and trivial-array fast paths; Lootbox Switchboard CPI crate's full 61-line
   module boundary. ABIv2 is experimental and requires runtime support; a scratch
   mapping cannot be imported into production Hopper by assumption. Pinapod's
   representation validity is distinct from business validation. Lootbox's typed
   external-program interface is a concrete integration DX pattern; its module
   documentation is not evidence that Hopper has a Switchboard integration.
